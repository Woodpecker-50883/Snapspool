# Snapspool 技術メモ（出典付き）

`requirements.md` から分離した調査結果。実装中に entitlements やAPIの可否を
確認したいときだけ読めばよい（毎周読む必要はない）。

### サンドボックス下でのフォルダ書き込み

- [確認済み] `~/Pictures` 配下への読み書きは `com.apple.security.assets.pictures.read-write`
  entitlement で可能。これは「ユーザーがダイアログで選んだファイル」とは別の仕組みで、
  **選択パネルなしに ~/Pictures へアクセスできる**。既定の保存先をここに置くのはこのため。
  出典: [com.apple.security.assets.pictures.read-write (Apple)](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.assets.pictures.read-write)
- [確認済み] `~/Pictures` 以外の任意フォルダは、Open/Saveダイアログでユーザーが選んだ場所への
  読み書きを許す `com.apple.security.files.user-selected.read-write` entitlement が必要。
  再起動後も同じフォルダへ書き込み続けるには、セキュリティスコープブックマークを
  保存して使う（`NSURL.bookmarkData` → 使用時に `startAccessingSecurityScopedResource`
  / `stopAccessingSecurityScopedResource` で囲む）。
  出典: [Enabling App Sandbox (Apple)](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html)
- [確認済み] ブックマークは `NSOpenPanel` でユーザーが選択した直後、パネルが解放される前に
  作る必要がある。`stopAccessingSecurityScopedResource` を呼び忘れるとカーネルリソースが
  リークし、再起動までサンドボックスへの場所追加ができなくなる。
  出典: [Apple Developer Forums #732593](https://developer.apple.com/forums/thread/732593)
- [要検証] `com.apple.security.files.bookmarks.app-scope` entitlement が実際に必須かは
  公式の一次回答が見当たらない（「無くても動く」という開発者の実験報告もある）。
  公式ドキュメントの記載通りまず付ける方針とし、挙動を実装時に確認する。
  出典: [Apple Developer Forums #798402](https://developer.apple.com/forums/thread/798402)
- [確認済み] アプリ自身のコンテナ（`Application Support/<bundle id>/`）への書き込みは
  entitlement不要。保存失敗時の退避先にこれを使う

### グローバルショートカット

- [確認済み] Carbonの `RegisterEventHotKey` は entitlement も権限プロンプトも不要で
  App Sandbox内・Mac App Store配布アプリで動く。これをMVPの方式とする
  （KeyboardShortcutsライブラリ等も内部でこの仕組みを使う）
- [確認済み] `Cmd+Shift+V` は登録可能。macOS Sequoiaで入った
  `RegisterEventHotKey` の制限は「shift / option のみの組み合わせ」が対象で、
  Cmdを含む組み合わせは影響を受けない（Appleのフレームワークエンジニア回答）。
  出典: [Apple Developer Forums #763878](https://developer.apple.com/forums/thread/763878)
- [確認済み] グローバルホットキーは最前面アプリより先にキーを受け取るため、
  `Cmd+Shift+V` を使う他アプリ（Slack / Notion / 各種エディタの「書式なし貼り付け」）では
  その機能が効かなくなる。Apple標準の「ペーストしてスタイルを合わせる」は
  `Cmd+Option+Shift+V` なので、標準メニューとは衝突しない
- [確認済み] 継続的なキー/マウス監視が必要になった場合は `CGEventTap` を使う。
  これは Accessibility ではなく Input Monitoring 権限で動き、サンドボックスとも両立する
  （`CGPreflightListenEventAccess` / `CGRequestListenEventAccess`、macOS 10.15以降）。
  MVPでは不要。
  出典: [Apple Developer Forums #811443](https://developer.apple.com/forums/thread/811443)

### 自動貼り付けの扱い（2026-10-16に方針変更）

- [確認済み] App Sandbox Design Guide は「`CGEventPost` のようなキーボード/マウスイベントの
  送出はサンドボックスの制限を回避する手段になるため、サンドボックスアプリからは許可されない」
  としている
- [確認済み] 一方でAppleのDTSエンジニアは、`PostEvent` TCC権限（`CGEvent.post` が使うもの）と
  `Accessibility` TCC権限は別物で、`PostEvent` / `ListenEvent` はApp Sandboxと両立すると説明している
- [確認済み] しかし実例として、クリップボード履歴アプリが
  「`NSPasteboard.general` へ書き込み → `CGEvent.post(tap: .cgSessionEventTap)` で ⌘V送出」
  という実装でガイドライン2.4.5によりリジェクトされ、スレッド上では未解決のまま
  他の開発者も同じリジェクトを報告している。
  出典: [Apple Developer Forums #820594](https://developer.apple.com/forums/thread/820594)
- [確認済み] **2026-10-16追記**: Maccyは `CGEvent(...).post(tap: .cgSessionEventTap)` で
  自動貼り付けを実装したまま、Mac App Storeで配布されている
  （[Clipboard.swift:143-148](https://github.com/p0deje/Maccy/blob/master/Maccy/Clipboard.swift)、
  App Store向けの条件分岐は見当たらず、entitlementsは `app-sandbox` 有効）。
  つまり**この実装でApp Storeを通る前例が実在する**
- → **自動貼り付けを実装する**。リジェクト報告も実在するため、落ちた場合は
  この前例を挙げてResolution Centerで反論する。権限が無い環境では手動 `Cmd+V` にフォールバックする

### 審査・公開

- [確認済み] App Store Connectにプライバシーポリシーのリンクが必須で、アプリ内からも
  アクセスできる必要がある。本アプリは通信・解析なしのため「データ収集なし」で記述できる。
  出典: [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
- [要検証] 「Snapspool」の商標の正式調査は未実施。Web・App Store検索では同名アプリは
  見つからなかった（ClipKeep / ClipNest / Pastory / ShotKeep / ShotNest / Shotstash /
  Shotori / Hikae / Snapstash は既存のため回避した）

### 参考: 先行アプリ

- [確認済み] Maccy（MIT / Swift / クリップボード履歴）は、撮影機能を持たず
  クリップボードを0.5秒間隔で監視して履歴化する。ファイルURL / HTML / PNG / RTF / 文字列 /
  TIFF を履歴対象にし、concealed / transient / autogenerated は無視する。
  entitlementsは `app-sandbox` + `files.user-selected.read-only` のみで、
  フォルダへのファイル保存機能は持たない。
  出典: [p0deje/Maccy](https://github.com/p0deje/Maccy), [Maccy.entitlements](https://github.com/p0deje/Maccy/blob/master/Maccy/Maccy.entitlements)
- [確認済み] ShotNest（macOSメニューバーアプリ）は、クリップボードを監視してコピーされた
  画像をPNGで `~/ShotNest/` に保存する。同じ作者のShotKeepはスクショのフォルダ整理に特化。
  いずれも「複数枚の画像履歴をショートカットで呼び出して選び直す」機能は持たない（[要検証] README記載ベース）。
  出典: [ShotNest](https://github.com/Nelahia/shotnest), [ShotKeep](https://github.com/Nelahia/shotkeep)
- → **Snapspoolの差別化点は「画像とテキストを混在させた履歴ピッカー（`Cmd+Shift+V`）+
  画像のフォルダ自動保存」の組み合わせ**。どちらか片方だけなら既存アプリで足りるため、
  実装の重心はこの組み合わせに置く
- [確認済み] Clipy（現在ユーザーが使用中）はテキスト履歴とスニペットを持つが、
  スクリーンショットを履歴に残せない。既定ショートカットが `⇧⌘V` でSnapspoolと衝突する。
  出典: [Clipy](https://github.com/clipy/clipy)
