# 判断の記録

`requirements.md` から分離した、判断の経緯と理由。
要件定義書は「現在の仕様」だけを書く場所にし、**毎周エージェントが読む量を抑える**ため、
こちらに移した（2026-10-16）。人間が経緯を追うとき、ブログの素材にするときに読む。

## 判断が割れた点・決定事項（一覧）

| 論点 | 選択肢 | 決定 | 理由 |
|---|---|---|---|
| 履歴の対象 | 画像のみ / 画像+テキスト | **画像+テキスト** | Windowsのクリップボード履歴と同じ体験にするため。Clipyを引退させて一本化する |
| スクショをどう取り込むか | 専用ショートカットを覚えてもらう / フォルダ監視 / **既存キーをクリップボード側へ付け替えてもらう** | **既存キーの付け替え** | アプリ専用のキーを増やさず、フォルダ監視でクリップボードの概念もぶらさない。macOSは「ファイル保存」と「クリップボードにコピー」で別々のキーを持てるため、ユーザーは今までと同じ指の動きで使える |
| スクショ設定の案内 | 無し / 初回起動時に案内 | **初回起動時に案内 + 後から再表示** | サンドボックス下ではアプリから設定を変更も検知もできず、未設定のユーザーにはアプリが無反応に見えるため |
| ファイル・フォルダのコピー | 履歴化する / 素通りさせる | **素通りさせる（最新1件はOS標準動作で使える）** | 過去のファイルを履歴から貼り直す必要はないとユーザーが判断。パス文字列がテキスト履歴に混ざる紛らわしさを避ける |
| Clipyの扱い | 併用 / 引退 | **引退** | 既定ショートカット `⇧⌘V` が衝突し、履歴も2つに分散するため。スニペット機能は失うがMVPの課題ではない |

## 各要件の詳しい理由

`requirements.md` では1文に圧縮してある理由の全文。

### 別々のショートカットとして

このアプリのために紛らわしいショートカットを増やさない、という方針。 ユーザー環境では 選択部分→ファイルに `⌃⇧S` を割り当てていたため、 同じ `⌃⇧S` を 選択部分→クリップボード に付け替えて運用する

### アプリが扱うのはクリップボードに入ったものだけ

「コピーしたものを一時的に保持する」というクリップボードの 概念をぶらさないため。フォルダ監視を足すと、コピーしていないものが履歴に現れる

### 連続コピーの取りこぼしは許容する

pasteboardの変更を通知する公式APIは見当たらず[要検証]、タイマーによる ポーリングが標準的な手法。Maccyも同じ方式を採る[確認済み]。 間隔を0.5秒から0.3秒へ詰めて取りこぼしを減らすが、原理的には残る

### ファイル・フォルダのコピーは素通りさせる

Snapspoolは監視中クリップボードを読むだけで書き込まないため標準動作は壊れないが、 ファイルコピーがパス文字列としてテキスト履歴に入ると、履歴から選んだときに 「ファイル」ではなく「パスの文字列」が貼られて紛らわしい。 履歴から過去のファイルを貼り直せる必要はない、とユーザーが判断した

### 書式付きテキストの扱い

変換経路を増やさないため。通常のアプリはプレーンテキスト表現を併記する

### 保存対象は画像だけ

テキストはコピー頻度が高く、1コピー1ファイルにするとフォルダが散らかる。 スクショをファイルとして残したいという元の課題は画像に固有のもの

### 履歴の保持

テキストをディスクに残さないことを ユーザーが選択した。機密性の観点でもディスクに残らない方が安全

### 自動貼り付け

当初はApp Store審査のリジェクト事例を理由にスコープ外としていたが、 Maccyが同じ `CGEvent.post(tap: .cgSessionEventTap)` による実装のまま Mac App Storeで配布されていることを確認した。原理的に不可能ではない。 実際に毎日使った結果、選んだ後にもう一度 `Cmd+V` を押す操作が 想定と大きく異なり不便だとユーザーが判断した

### ショートカットは押して記録する

Windowsのクリップボード履歴は `Windows+V` で開く。その位置に当たるキーへ割り当てたいという ユーザーの要望があり、固定リスト方式では表現できない組み合わせがあった

### 初回起動時に案内を表示する

この設定をしていないユーザーにとって、アプリはスクショに対して無反応になる。 アプリからは設定を変更も検知もできないため、案内だけが手段になる

### Why

ユーザーの希望。ただし一部アプリの「書式なし貼り付け」を奪うため、 変更可能であることが前提条件。後述の「判断が割れた点」参照
