# Mac App Store 公開の手順（丁寧版）

初めてMacアプリを出す前提で、何を・なぜやるのかを順に書いたもの。
作業の全体像を先に掴んでから、上から順に進める。
短いチェックリストが必要なときは `docs/release-checklist.md` を見る。

---

## 0. 全体像：公開に必要なものは3つだけ

公開作業は複雑に見えるが、要求されているのは次の3つに集約される。

| # | 何を証明するか | 具体物 |
|---|---|---|
| 1 | **誰が作ったか** | Apple発行の証明書で署名されたアプリ |
| 2 | **何のアプリか** | App Store Connectに登録したアプリ情報（名前・説明・スクショ・URL） |
| 3 | **何をするアプリか** | 審査に通る中身（ガイドライン適合・プライバシー申告） |

いまSnapspoolは「3」がほぼ完成していて、「1」と「2」がこれからの作業になる。

---

## 1. 下準備（Apple側の登録）

### 1-1. Apple Developer Programに入っているか確認

年額99ドルの有料プログラム。**保有済みと聞いている**ので、ここは確認だけ。

https://developer.apple.com/account にログインして、
「Membership details」にStatusがActiveと出ていればよい。

> なぜ必要か: 無料アカウントでは自分のMacでしか動かないアプリしか作れない。
> App Storeへの配布には有料プログラムが要る。

### 1-2. App ID（バンドルID）を登録する

アプリを世界で一意に識別する文字列を、Appleに予約する作業。

1. https://developer.apple.com/account/resources/identifiers/list を開く
2. 「+」→ **App IDs** → **App** を選ぶ
3. Description: `Snapspool`
4. Bundle ID: **Explicit** を選び、`app.snapspool.Snapspool` と入力
5. Capabilities: 特別な機能（iCloud、プッシュ通知など）は使っていないので**何も追加しない**
6. Continue → Register

> ⚠️ **バンドルIDは後から変更できない**。入力ミスに注意。
> 既にアプリ内で `app.snapspool.Snapspool` を使っているので、これと完全に一致させる。

### 1-3. チームIDを控える

https://developer.apple.com/account の「Membership details」にある
**Team ID**（英数字10桁）をメモする。ビルド時に使う。

---

## 2. App Store Connectにアプリを作る

ここが「ストアに並ぶ情報」の置き場所になる。

1. https://appstoreconnect.apple.com → 「マイApp」→ 「+」→ **新規App**
2. 入力内容:
   - プラットフォーム: **macOS**
   - 名前: `Snapspool`
   - プライマリ言語: 日本語（英語も後から追加できる）
   - バンドルID: 1-2で登録したもの（プルダウンに出る）
   - SKU: `snapspool-1`（自分用の管理番号。何でもよいが後から変えられない）
   - ユーザーアクセス: 「フルアクセス」
3. 作成

この時点ではまだ何も公開されない。空の棚ができただけの状態。

---

## 3. アプリの情報を埋める

作成したAppのページで、左メニューから各項目を埋めていく。
**文面はすべて `docs/app-store-metadata.md` に用意済み**なので、コピーして貼るだけ。

### 3-1. 「App情報」

- サブタイトル: 用意済みの文言
- カテゴリ: **仕事効率化**（プライマリ）
- 権利（著作権表記）: `2026 <あなたの氏名または屋号>`

### 3-2. 「価格および配信状況」

- 価格: **無料**
- 配信地域: 全世界（絞ってもよい）

### 3-3. 「Appのプライバシー」（忘れやすい・重要）

ここは質問に答えていく形式。Snapspoolの正解はシンプルで、
**「データを収集しません」を選ぶだけ**。

1. 「データ収集」の質問で **「いいえ、このAppからデータを収集しません」** を選ぶ
2. プライバシーポリシーURLを入力（手順4で用意するもの）

> なぜ重要か: ここの申告と実際の挙動が食い違うと、審査で落ちるだけでなく
> 公開後の削除対象にもなる。Snapspoolは本当に何も送信していないので、
> 正直に「収集しない」と答えれば正しい。

### 3-4. バージョン情報（1.0）

- 説明: 用意済みの本文
- キーワード: 用意済み
- サポートURL: 手順4で用意するもの
- スクリーンショット: 手順5で撮るもの
- **Appレビューに関する情報 → 「メモ」**: 用意済みの審査メモを貼る

---

## 4. 2つのURLを用意する（あなたの作業）

App Storeは**プライバシーポリシーURL**と**サポートURL**の2つを要求する。
どちらも「誰でも見られるWebページ」である必要がある。

### 4-1. プライバシーポリシー

文面は `docs/privacy-policy.md` に日英とも完成している。
末尾の連絡先の `TODO` だけ埋めて、次のどれかで公開する。

**おすすめ: GitHub Pages**

1. GitHubでこのリポジトリの Settings → Pages を開く
2. リポジトリをPublicにする必要がある（ソースも公開される点に注意）
3. 公開したくない場合は、**文書だけの別リポジトリ**を作ってそこに置く

**手軽な代替: Gist**

1. https://gist.github.com で新規作成
2. `privacy-policy.md` の中身を貼り付けて **Public** で保存
3. そのURLを使う

### 4-2. サポートURL

問い合わせ先が分かるページであればよい。
公開リポジトリのIssuesページ（`https://github.com/<user>/<repo>/issues`）で要件を満たせる。

---

## 5. スクリーンショットを撮る（あなたの作業）

**仕様**: 16:10の比率で `1280×800` / `1440×900` / `2560×1600` / `2880×1800` のいずれか。
PNGまたはJPEG、**透過なし**。最低1枚、3枚以上を推奨、最大10枚。

推奨する4枚と撮り方は `docs/app-store-metadata.md` に書いてある。

撮影時の注意:
- 履歴の中身に個人情報が映らないようにする（ダミーの内容に差し替える）
- メニューバーに他アプリのアイコンが並ぶので、気になるなら整理してから撮る
- **実装の残り3件が終わってから撮る**（メニュー項目が増えるため、撮り直しを避ける）

---

## 6. ビルドを作ってアップロードする

**実装の残り3件が完了してから**行う。

### 6-1. チームIDを設定してアーカイブ

```bash
cd ~/dev/projects/Snapspool
xcodegen generate --spec xcodegen.yml
xcodebuild archive -scheme Snapspool -destination 'platform=macOS' \
  -archivePath build/Snapspool.xcarchive \
  DEVELOPMENT_TEAM=<手順1-3で控えたチームID>
```

> アーカイブとは、配布用に署名された状態で固めたもの。
> 普段のビルドとは別物で、これをAppleに送る。

### 6-2. Xcodeからアップロード

1. Xcodeを開く → メニューの **Window → Organizer**
2. 左の「Archives」に `Snapspool` が出る（出ない場合は手順6-1の成果物をダブルクリック）
3. **Distribute App** → **App Store Connect** → **Upload**
4. 署名は「Automatically manage signing」で進めてよい
   （証明書とプロビジョニングプロファイルをXcodeが自動で作る）
5. アップロード完了まで数分

> ⚠️ ここで署名エラーが出ることが多い。多くは「Apple Developerのサイトで
> 使用許諾の更新に同意していない」ことが原因。その場合は
> https://developer.apple.com/account にログインすると同意画面が出る。

### 6-3. 輸出コンプライアンスの質問に答える

アップロード後、App Store Connectで「暗号化を使用しているか」と聞かれる。

**Snapspoolの答えは「いいえ」**（通信も暗号化も行っていないため）。

毎回聞かれるのを避けたい場合は、`Info.plist` に
`ITSAppUsesNonExemptEncryption = false` を入れておくとよい（未設定なので、
入れるなら実装タスクとして追加する）。

## 7. 審査に出す

1. App Store Connectのバージョンページで、アップロードしたビルドを選択
2. すべての必須項目が埋まっていることを確認（赤い警告が消える）
3. **「審査へ提出」**

### 審査の目安と流れ

- 初回審査は**24〜48時間**程度のことが多い（前後する）
- 結果はメールとApp Store Connectの通知で来る
- 通れば「配信準備完了」。手動リリースを選んでいれば、自分のタイミングで公開できる

### Snapspoolで特に見られそうな点

| 懸念 | こちらの備え |
|---|---|
| クリップボードを監視するアプリであること | 審査メモで「通信なし・収集なし・ローカル完結」を明示済み |
| 自動貼り付け（キーイベント送出） | 実装している。同種アプリ（Maccy）が同じ `CGEvent.post` の実装のままMac App Storeで配布されている前例がある。ただしガイドライン2.4.5でリジェクトされた報告も実在するため、**落ちた場合はResolution Centerで前例を挙げて反論する**。審査メモにも、権限は明示的な許可時のみ・設定でオフにできる旨を記載済み |
| プライバシーポリシーへの到達 | アプリ内メニューからの導線を実装予定（残タスク） |
| サンドボックス | 有効のまま動作することを確認済み（`codesign -d --entitlements -`） |

### 落ちたときは

リジェクトは珍しくない。通知に理由（ガイドラインの番号）が書かれているので、
それを読んで直すか、**Resolution Centerで反論する**。
反論は正当な場合に通ることもある。感情的にならず、事実と挙動を説明する。

---

## 8. 公開後

- バージョンを上げるときは `CFBundleShortVersionString`（1.0→1.1）と
  `CFBundleVersion`（1→2）を上げてから、同じ手順でアップロードする
- `CFBundleVersion` は**同じ値での再アップロードができない**ので、毎回必ず上げる

## いま詰まりやすい順（優先度）

1. **URLを2つ用意する**（手順4）— ここが無いと申請画面が完了しない
2. **App Store Connectでアプリを作る**（手順2）— 先に作っておくと以降が楽
3. **スクリーンショット**（手順5）— 実装完了後に撮る
4. **アーカイブとアップロード**（手順6）— 署名で詰まりやすいが、Xcodeの自動管理でたいてい解決する
